# Discipline 10: bounded hidden-rubric pass on ungated prose

Status: PRACTICE, not code. This procedure is the mechanism. No generic
scorer ships, because a scorer that cannot read for meaning would manufacture
confidence, not quality.

## When

Run this pass on a deliverable no gate covers: a read, a synthesis, a
recommendation, a report. Code and artifacts with real gates use their gates
first; this pass covers the prose judgement those gates cannot reach.

## Procedure

1. Construct a task-specific rubric of five to seven categories from the
   role's point of view: the person who must act on the prose. Write each
   category as a question the draft either answers or fails.
2. Set one global threshold before scoring. Do not move it after seeing the
   score.
3. Score the draft against the rubric internally. The rubric stays internal;
   the reader receives the deliverable, not the scaffolding.
4. Revise once against the weakest category. The loop is bounded: at most
   two revision rounds. Then ship the best version with the weak dimension
   named in the delivery note or the work record.
5. Maintain the prompt subtractively: when a rubric line or instruction is
   shown not to work, delete it and cite the failure, instead of only adding
   new lines.
6. Remove unsupported emotional-pressure devices (tips, penalties, career threats)
   when they add no verifiable requirement. Preserve the substantive obligation
   and incident evidence. Treat wording efficacy as a local evaluation question,
   not a universal claim about every model.

## Rubric template

```text
Deliverable:
Reader role:
Global threshold: __ / 10

1. [category as a question]  score __  evidence in draft:
2. [category as a question]  score __  evidence in draft:
3. [category as a question]  score __  evidence in draft:
4. [category as a question]  score __  evidence in draft:
5. [category as a question]  score __  evidence in draft:

Weakest category:
Revision round 1 changed:
Revision round 2 changed (if used):
Shipped with this weak dimension named:
```

## Failure forms

- An unbounded revise-until-perfect loop. Not adopted; the cap is the point.
- Showing the user the rubric instead of the deliverable.
- Scoring against categories copied from another task. The rubric is built
  from this task's reader, every time.
- Claiming the pass is a gate. It is a bounded quality practice, and an
  adoption record grades it NOT CODE.
