# Efficiency Breakthroughs

## Why this skill exists

The default: treating every pipeline failure as a local bug in the script that happened to report it, and every slowdown as a reason to add retries.
The cost: the same transport, paging, caching, and reconciliation defects recur under new names for months, each debugged from zero, while the fixes that actually ended them live in incident logs nobody re-reads.
The replacement: this skill owns the mechanics underneath the core skill's efficiency law. Section 3 of the core skill ([infinityblade](../infinityblade/SKILL.md)) governs the general discipline: measure the complete path, fix the dominant stage, never buy speed by weakening a check. This file restates none of that; it carries the concrete mechanisms for moving data completely, surviving hostile transports, and proving what arrived. [lessons-from-the-field](../infinityblade/references/lessons-from-the-field.md) owns the failure patterns and the diagnosis loop; where the two overlap, the pattern governs the diagnosis and this file governs the mechanism.

Each discipline below is stated as a mechanism, with the episode that taught it. Workload figures are retained because they make the diagnosis concrete; they describe specific incidents, not promised benchmarks.

## Scope of the incident-derived mechanisms

Each episode remains intact as historical evidence. Its exact timeout, worker count, memory cap, tolerance or retry count is a workload-specific observation, not an automatic rule for every host. Optimization fallbacks must preserve the same canonical algorithm and source contract; they cannot silently restore a retired source of truth. A permission denial is an authority boundary, even when other tools can perform a similar write. Prove a platform-fault hypothesis with bounded authorized probes rather than assuming correlated failures share one cause.

## Part I: Moving data completely

**1. Page by opaque token, dedupe by ID, distrust silent defaults.** Walk a paginated endpoint by its opaque page token to exhaustion; never advance a cursor by a value that can tie (a date, a timestamp, a name), because every row sharing the cursor value past page one is silently dropped. Dedupe by the source's record ID while aggregating. Treat a successful response with a null or empty default as an under-specified request, not as no data: pass explicit windows, follow the next-page token, and slice the newest records client-side when the API returns the earliest page. When batching many symbols or items into one request, size the batch by a points budget (items times records per item against the page cap), not by item count.
*Episode:* a fee walk over a typed endpoint advanced its cursor to each page's maximum activity date and returned -11.62 of a true -243.93 across 166 rows; the token walk recovered the full total (2026-11-03). A bars API returned `{"bars": null}` with HTTP 200 whenever the caller omitted an explicit start (2026-09-27).

**2. Bulk transport: enumerate, split at the proven part size, checkpoint by content hash.** Before any large save, enumerate the set: count, total size, largest file. Split files over the host's proven ceiling into parts of a size proven by a direct test, with the original size and hash recorded beside them; run two passes, a fast pass that defers oversize files and an inventory-driven split pass that uploads whatever the remote census shows missing. Build trees as deltas on the base tree, listing only changed and deleted entries; chunk tree creation and chain the chunks. Checkpoint by content hash: compute each file's blob hash locally, compare against one recursive remote-tree fetch, skip what matches, and persist the stage reached, so a restart resumes from the verified count instead of zero. Stream-commit bounded batches as they fill rather than one giant tree at the end. Verify at the destination through the authoritative API by hash, never through cached raw or CDN URLs, which serve stale copies for minutes after a successful write; for files too large for the contents API to decode, compare blob hashes. Converge mirrors on tree identity, not ancestry: on a lost race, re-read the ref and merge only the writer-owned delta onto the new base, preserving unrelated concurrent paths. Re-parenting an unchanged whole-tree snapshot is valid only for an explicitly authorized exclusive mirror; on a shared tree it can silently delete another writer’s work. Verify the expected merged tree before compare-and-swap; never blind-force.
*Episodes:* whole-file uploads above roughly 25 MB stalled or were refused; a direct 20 MB blob POST proven in 11.2 s became the part size (2026-10-26). One 2,509-file, 2.5 GB tree POST was refused on consecutive runs until trees were built chunked and incrementally (2026-10-30). A collect-then-push save lost 25 minutes of uploads to a restart; stream-committed batches lost nothing already uploaded (2026-10-30).

**3. Stage channel-bound artifacts as byte-exact chunks plus a hash manifest.** When the only channel to a consumer cannot carry the artifact (a message drop, a size-capped store, an airlock), split it into byte-exact chunks of a proven size, ship them numbered with a SHA-256 manifest in a location restricted to the intended reader, and verify the hash chain at both ends against the source checkpoint and the reassembled head before anything downstream consumes it.
*Episode:* a 160,899-row producer ledger moved as 19 chunks plus a manifest; a delivered tail slice of 9,469 rows (19,981,135 bytes) verified against checkpoint and head hashes at both ends (2026-11-03).

**4. Replace full reseals with a watermark incremental save.** A periodic full reseal of a large tree spends nearly all of its cost re-proving what did not change, and its failures are total. Instead: save the small always-changing core in full every run, plus only the files new or changed since a persisted watermark, pushed individually under a per-run cap; keep the watermark and a consecutive-failure count in a state file, stay silent on success, and choose a documented failure-alert threshold against the recovery-point budget. The incident used the second consecutive failure; a first failure that endangers the only durable copy must surface immediately.
*Episode:* a five-minute full-reseal regime ended at receipt sequence 72, incomplete, with the last proven full seal at sequence 33; the nightly watermark replacement eliminated the reseal cost per cycle (2026-11-03).

**5. Many writers, one landing.** When several writers share one repository, each writer commits from its own worktree or a temporary index (hash each file once, build the tree, commit-tree) and lands through a single compare-and-swap ref advance. On a lost race, rebuild on the new base reusing the captured blob IDs, never re-reading live files; skip the commit when the tree equals the base tree. One landing process takes entries in order, runs the full gate against the immutable candidate commit, and advances the main ref only on green. Keep runtime state (caches, snapshots, state files) out of the source tree entirely; state churn in the tree races every gate and sweep.
*Episode:* the architecture was distilled from a multi-writer commit study after hand-merged writers repeatedly raced each other's commits (2026-10-13).

## Part II: When the transport fights back

**6. A 409 is two different failures; name which one before retrying.** A contents-write 409 carrying a SHA mismatch is a concurrent-writer race: another writer moved the head between your read and your write. The cure is a supervised serial re-run with read-back verification, not debugging your payload. A 409 reporting a rule-validation timeout is a transient on the host's side: re-run including the exact file that timed out. In both classes the failed run appends no proof line, so the missing line is the tell. Never start a dependent leg on an interim signal from a leg that is still running; that is how the second and third races of the same day happen.
*Episodes:* three SHA races in one day, each cured by a supervised re-run verified by read-back (2026-11-02); a rule-validation-timeout 409 on one file cured by the re-run that included it (2026-11-03).

**7. Transport discipline: timeouts always, fresh connections on reset, decode what you advertise.** Set connect and read timeouts on every call; no timeout means the indefinite hangs you will eventually get. On a connection reset, discard the connection, reconnect, and retry the content-addressed operation rather than reusing a pooled corpse. Decode every content encoding your client advertises, and fail closed on one you do not support. Know your library's defaults before blaming the server: a popular retry helper excludes POST from its defaults and omits some statuses from its honour-the-reset set, so both must be hand-coded. Keep one shared transport per service so a transport-level defect is cured once, in one place.
*Episode:* large nested payloads broke a naive reader with incomplete reads until the transport changed; bodies truncated through an egress proxy traced to one HTTP library's unconditional close header, cured in the single shared transport (2026-10-24).

**8. Diagnose in the failing context, and change one variable per probe.** When a call works from your shell and fails under supervision, the defect is in the delta between the two contexts: environment the service does not inherit (proxy, CA bundle), a missing HOME making tilde paths resolve to the wrong account, a library default the shell client does not share. Enumerate the delta and test each item separately. Before declaring a credential or an endpoint dead, run one exact control probe that varies a single property, ideally through a second client.
*Episode:* a valid API key failed with 401 across five probes because a client/header-path incompatibility changed the authentication request; one exact-case probe through a second tool proved the key good and the probe broken. HTTP field names are case-insensitive by specification; a casing-dependent result identifies a client/intermediary/server defect or a changed value, not a general case-sensitive-header rule (2026-10-24).

**9. When many unrelated writers fail the same way at once, it is one platform fault.** Intermittent write failures that arrive in minutes-long waves across unrelated scripts, directories, and temp roots are a property of the box, not of the scripts. Prove it once with an exhaustive probe matrix during a wave and again after it passes, then stop debugging scripts until the platform clears. During a wave, detached launches can die silently with empty logs; judge by visible output and effects, and prefer a transport that still works (shell writes kept working while one language runtime's writes were denied).
*Episode:* a full open-flag matrix failed during a wave and passed 92 of 92 minutes later; the single fault explained that day's sync, lane, collector, and poll failures (2026-11-02).

## Part III: Rate limits and caches

**10. Rate limits are architecture, not retries.** One designated writer fetches from the rate-limited source into a canonical local store; every consumer reads the store, so duplication across N processes collapses to one fetch per key. Hold one cross-process token bucket at about 85 percent of the ceiling, with reserved shares for the work that matters most and bulk research shed first; work whose deadline passes in queue is dropped, not served late. After consecutive 429s, open a global breaker and make zero upstream calls for the cooldown: a cascade of polite retries is still a cascade. De-synchronise recurring schedules by a hash offset instead of firing everything at the top of the minute, and jitter cache TTLs so warmed keys never expire together. Retry by class: on 429 wait for the told reset time rather than backing off against it; on 5xx use jittered backoff; do not blindly retry other 4xx. Resolve the specific 409 concurrency/version cases in discipline 6 by re-reading state and rebuilding the intended write; respect permanent permission/validation failures and idempotency constraints. (Retry accounting inside durable queues is owned by discipline 15 of the enhancement reference.) Assert your outbound pacing floor in a test, so courtesy is mechanically checked rather than remembered. Use conditional requests for polling where the host supports them; a not-modified answer saves transfer, but quota treatment is provider-specific and must be verified against the current endpoint contract.
*Episode:* an audit found 40 consumers of one market-data API with only 2 using the shared cache, top-of-hour bursts of 150 to 210 requests per minute, and a 1,838-symbol screen that collapsed to a handful of points-budgeted requests (2026-10-13).

**11. Cache semantics: immutable past, classified negatives, gated warmers.** A completed observation is stored immutably with its observed version; a closed interval is not a promise that its provider can never revise it. Keep forming records separate, and define a correction/adjustment refresh policy for revised bars, corporate actions and vendor repairs. Preserve the prior observation and supersession provenance instead of silently overwriting it. Skip redundant fetches only inside the source’s validated revision horizon. The cache key carries the feed and adjustment basis, so two bases never silently mix. Negative caching is classified by cause: a transient no-data answer is cached briefly, a confirmed-gone answer until the next session (verified once against the authoritative registry), and a 429, 5xx, or timeout is never negative-cached. A warmer rebuilds only when its output is missing or older than its TTL, backs off after failure with the failure named, and is registered before the readers that serve its output. Warm exactly the missing pairs, never the whole system. When a history minimum cannot accrue live in reasonable time, backfill in one batched call and merge into the single existing series by timestamp, live values winning their timestamp, failing closed on a stale newest row.
*Episodes:* a 576-request-per-hour re-fetch job over completed bars became at most 2 requests per day once completed intervals were write-once (2026-10-13). A global warm step fetched the entire system's data per timeframe and died at its 1,800-second timeout; warming only the missing pairs finished in about 50 seconds (2026-11-02).

**12. Skip and memoize on input fingerprints, never on output hashes.** Memoize repeated parses and loads on a fingerprint with declared strength: (mtime_ns, size) is a fast cache heuristic, not proof of byte identity. Use a content hash or trusted immutable version when correctness depends on detecting equal-size rewrites with preserved timestamps, and prove the memoized path byte-identical on outputs before trusting it. Gate recomputation and publication on the inputs (maximum updated_at, plus count, plus schema version, or a monotonic sequence), because hashing rendered output saves nothing: the generation already happened before the hash. Serialize only dirty sections and reuse untouched bytes verbatim.
*Episode:* a large cache file re-parsed on every cycle cost 1.32 seconds until parses were memoized on its (mtime_ns, size) key with freshness semantics unchanged (2026-10-25).

## Part IV: Running it unwatched

**13. Calibrate the watchdog to the measured system.** Supervise by effects (the worker's own post-work heartbeat plus live process identity), never by process existence alone. Size the grace from the measured cycle period, roughly twice the period plus a separate wedged threshold, not from the period you hoped for. Give starting processes a launch-age grace: a relaunched worker's status still names the previous process until its first slow cycle lands. Cap restart intensity per window and, past the cap, enter a named DEGRADED state instead of storming. Enumerate live instances directly and refuse to launch while any instance lives; one owner per stream of work, enforced with a lock. Propagate one deadline object: every downstream timeout is the minimum of its own cap and the remaining budget, and retries spend the same budget. Quarantine a poison item after repeated kills at the same cursor. A monitor can only supervise what its listing scope can see: verify the monitor's census before trusting its calm, and put persistence guardians in the layer that actually persists, not in configuration the platform rebuilds. Overlapping invocations of the same job skip and receipt as served, never run twice. External alert watchers need transition damping and a flap test before going live.
*Episodes:* a 180-second grace against a measured 275-second cycle caused 33 churn restarts a day (2026-10-25). Judging a starting process by its predecessor's heartbeat relaunched it three times in one minute (2026-10-24). An undamped external watcher sent about 50 down/up emails in a day and was retired at the source (2026-10-23).

**14. Parallelize without changing the answer.** Assign pooled work longest-cost-first, with costs learned from completed runs and unknown tasks priced at the median known cost; round-robin in roster order stacks half the roster behind the single slowest task. Parallelize independent fetches, but consume results in the original order, stop at the exact point the sequential walk stopped, and aggregate in original order. The output of the parallel version must be byte-identical to the sequential one; if it is not, the parallelization is a behavior change wearing a costume.
*Episode:* parallel day and page fetches consumed in original order cut a cold-cache cycle from 438.7 seconds to 114.4 seconds with identical output (2026-10-24).

**15. When the consumer is pinned, pre-aggregate outside it.** If an expensive transform is re-derived every pass by a component you must not modify, pre-aggregate outside it and serve the result through the input door it already reads, in the shape it already expects: complete aligned buckets only, a small content-keyed cache, and memoized windows. On any anomaly (duplicate starts, an unparseable row, a producer-supplied result), decline to the original path untouched rather than serving a doubtful aggregate.
*Episode:* a pinned strategy called a linear session scan 11,324 times per pass; the outside pre-aggregation cut evaluation from 5.40 seconds to 1.09 and aggregation from 6.32 to 0.049 (2026-10-25).

**16. Process-pool hygiene: prime the parent, scope the paths, serialize inside the guard.** Before spawning a pool, make every module a worker might raise from importable in the parent: worker exceptions must be picklable in the parent, or the first real error breaks the whole pool and reports every pending item as wreckage. If a builder converts wreckage into excluded-by-name rows, a poisoned run destroys its own output manifest; treat a poisoned run ID as unretryable and rebuild under a fresh ID. Normalize domain objects to contract dicts at the worker boundary, serialize inside the guard, and degrade an unserializable result to a named per-item error instead of a dead worker reported as bare EOF. Scope every sys.path insertion to the single import that needs it and always remove it; an insertion left in a long-lived pooled worker shadows package names for every later task that worker runs.
*Episodes:* one unpicklable worker exception rewrote a 1,809-item build manifest as 9 built (2026-11-02). A vendor path inserted at position zero and never removed shadowed a top-level package for 18 later consumers in the same worker (2026-11-02).

## Part V: Trusting what arrives

**17. Validate at the seam, once, as a whole.** Census the fetchers first and put the gate at the one choke point every item passes through, not in each of dozens of scripts. Revalidate at delivery time, not production time: age is computed on receipt; too-old, future-dated beyond a small skew, or unstamped items are dropped by name and their cache entries deleted. Validate an ingested payload as a set, not row by row: an unrequested member fails it, duplicate or non-increasing keys fail it, a per-item lag drops and names only that item. Cap intake (file size, row count, field length), refuse the whole file on unknown or duplicate columns, refuse fixture- or sample-labelled sources as real input, and return per-row rejection reasons with line numbers while absent fields stay null. At the single write choke point, stamp each record with a hash of its canonical serialization so bypasses are detectable. Boundary failures go to an append-only quarantine with natural key, reason code, payload hash, and a retryable flag: never silently dropped, never passed downstream, replayed through the same validator under the original idempotency key. Fan-out fetches isolate failure per item: the fetch fails only when every item fails, and a producer that returns empty while carrying an error is recorded as an error, because health that only records raised exceptions makes a total outage invisible.
*Episodes:* a survey of 98 refresh scripts found exactly one fetching a live quote; the freshness gate wired at that single entry point covered the system (2026-10-29). A fetch that raised on its first bad symbol darkened 46 dependents while the producer-error record stayed empty (2026-10-25).

**18. Freshness is a contract on content timestamps, never on file mtime.** Judge freshness on three distinct values: the maximum event time inside the data, checked against the calendar-derived expectation including the expected record count so far; the last successful load time, so steady data is not flagged stale and a stalled pipeline cannot masquerade as fresh; and a generated_at stamp inside every published payload. Keep one registry row per expected product (producer, product, sequence or load field, warn age, error age, cadence) and run the checker on its own schedule, never inside the producer's pass. Name three alert classes distinctly: never registered, registered but stale, present but gapped. A family orchestrator stamps one shared freshness token on every consumer and fails unless all agree; a consumer whose sources disagree keeps serving its last good state under a stale stamp with the reason named. Every freshness gate needs a scheduled generator and an aging invariant check that goes red the moment an output passes its bound; a correct gate fed by a manual-only generator fails closed forever and teaches everyone to ignore it.
*Episode:* a drill found yesterday's bars carrying a fresh file mtime passing as current until freshness moved to content timestamps (2026-11-02).

**19. Redundant representations must agree, in shape and in count.** A producer owes every mode the same shape: a value that is a list in live mode and a dict in evaluate-only mode is a defect at the seam, invisible precisely because an empty dict iterates like an empty list. Counts must agree across every redundant representation (card, full list, ledger) or publication refuses, idempotently. Fixtures must carry the live shape: a consumer that accepts only the fixture shape and discards the live one reports zeros behind a green gate. Consumers carry values verbatim and never fabricate attribution or breakdowns the source does not contain.
*Episodes:* a dict served where every consumer expected a list left 178 consumers erroring with zero orders across a weekend (2026-10-26). A display layer accepting only the dict shape reported zero positions every cycle while its dict-shaped fixtures kept the gate green (2026-10-27).

**20. Empty, missing, and defaulted are three different states.** An empty result is a valid value: serve an empty list as-is, and reserve the missing-key error for a payload carrying no such list under any key. Absent fields are represented as absent (null), never as a fabricated zero; a fallback delta of 0.0 presents an invented value as measured. Read the real schema key before reading a document: a defaulted fallback on the wrong key returns a silent empty that looks exactly like no data, and a blind rewrite on that reading can destroy the index.
*Episodes:* reading a manifest under a guessed key yielded an empty list while the data lived under its real key (2026-09-30). A serving branch that required a non-empty list reported an honest empty result as a missing key and starved three consumers (2026-11-03).

**21. Source trust is earned by reconciliation, and stamped honestly.** Disqualify a source for a use by paired-fetch reconciliation: pull the same quantity from two sources and compare the aggregates; investigate which source violates the independent oracle and disqualify it for the demonstrated use/version/window in writing. Two disagreeing sources alone do not identify a winner. Record the defect, chosen source, receipt and revalidation trigger; a repaired source can earn readmission. Fall back per key and per period across source tags, never first-tag-wins for all keys. Stamp the feed and basis you actually got: when a tier refuses the requested feed, request the tier that answers, record its true name, keep the data's own timestamps, and never re-stamp delayed data as fresh. A source's known traps are recorded beside its consumer; this discipline is how entries earn their place there.
*Episode:* one source's hourly volumes summed to 268.7 million against its own 20.8 million daily total, morning bars running 13 to 48 times the tape, while a second source's hourly figures summed to about 19.1 million reconciling cleanly; the first source was disqualified for hourly volume and the second adopted (2026-10-09).

**22. Normalize at the one boundary every item passes through.** Convert formats inside the single adapter helper all items of a family traverse, never inside each consumer: one conversion site fixes the family and its siblings. Convert only the forms that need it; a partial conversion rule that also transforms forms a downstream gate parses natively will break that gate, so scope the rule to the exact form (full timestamps, not date-only strings). Drop aliased duplicate keys at the same boundary (one series served under several suffixed keys makes consumers emit phantom entities), and resurface an item served only under an alias under its plain name so coverage is never lost. Trim a still-forming trailing record before completeness validation rather than dropping every series, and apply unit multipliers per instrument type at the boundary, because a price can be per-unit while quantity is in contracts.
*Episodes:* string timestamps converted in the one adapter helper fixed a whole family; broadening the rule to date-only strings broke a staleness gate and was caught by it (2026-10-26). Aliased keys dropped at the boundary cured a family of phantom-entity rejections at one site (2026-10-27).

## Part VI: Keeping the books

**23. Reconciliation that converges.** Sweep the system of record for late-arriving events before every discrepancy check, journal only the cumulative delta under the original attribution marked as imported, and make the sweep idempotent; a journal written only from one immediate read-back diverges permanently from anything that completes later. Scope derived truth to its epoch: after a baseline or account change, filter journal-derived truth to the new epoch and re-derive any dependent offset in the same pass, because an offset solved against the old scope manufactures a new discrepancy. Pin a baseline's inputs at record time (the roster total as it was, not as it is now), and when an evidence read fails, skip only that check with a named reason instead of halting on missing data. Before adding any term to a reconciliation, test whether it is already netted inside another figure; adding a netted term is a double count, and the cheapest proof is that the error moves by exactly the term. Fold state-dependent values at the granularity of the state: an in-kind fee's cash value is real only when its own position generation closes, so a symbol-level rule misstates the book in both directions across different weeks. Bound continuous reconciliation to open items plus a watermark delta and reserve full-history derivation for a periodic audit. Report the full discrepancy at the strict tolerance, but halt only on the unexplained remainder above a materiality bound (0.1 percent of expected value in the proven case); carry below-bound remainders open by name. Never force-edit the ledger to match: book a correcting entry that references the discrepancy's ID.
*Episodes:* 56 submitted orders against 21 recorded fills diverged a journal until the pre-check sweep imported the delta and cleared every discrepancy (2026-10-30). A baseline re-derived from a grown roster (313 to 336 members) manufactured a 230,000 phantom discrepancy (2026-10-30). A fully explained 0.45 residual, and a rounding-scale 228.23 on a 1,009,113.61 book, each idled the entire operation until halts were scoped to the unexplained remainder (2026-11-02 and 2026-11-03).

**24. Compare in decimal, at the magnitude it will actually run at.** A binary-float subtraction at live magnitude (1077786.01 minus 1077786.0 leaves 0.010000000009313226) exceeds a one-cent tolerance that toy-scale fixtures always satisfy. Parse authoritative decimal amounts from strings and compare with decimal arithmetic at the declared precision. Quantize operands only when the domain contract explicitly defines that rounding; blindly rounding the difference can admit an out-of-tolerance value (for example 0.014 becoming 0.01). Test the exact boundary, a just-outside value and the live magnitude: a toy-scale fixture proves a different, easier claim.
*Episode:* an exactly-in-tolerance residue halted a whole pipeline until the comparison was made in decimal at live magnitude (2026-10-31).

**25. Preflight what the receiver will reject, and what the book already satisfies.** Reject locally, with named reasons, only the shapes already proven to fail at the receiver (malformed identifiers, untranslatable dialects, mutually exclusive fields); warn instead of rejecting on unproven shapes, and scope each rule to exactly the class its evidence names, because a rule written for one emitter class that also catches another will outlive the restriction that justified it. Do not apply entry-only strategy filters to legitimate exits, so a held position stays closable. Exits still require authority, valid account/symbol identity, receiver-compatible shape and position/quantity bounds. Before any state-changing request, reconcile it against the book of record: no position means the request is already satisfied and terminates unsent (sending it would open the opposite position), the side is derived from the real position's sign, and quantity is clamped to the position net of resting reservations.
*Episodes:* a preflight validator removed deterministic receiver rejections at zero network cost; one over-scoped rule broke unaffected emitters' round-trips and was narrowed by name (2026-10-30, amended 2026-11-02). Exits preflighted against the real book drained 840 queued phantom exits to zero in one pass (2026-10-29).

**26. Errors carry their evidence.** An HTTP layer that reads and discards the response body makes every rejection undiagnosable from the system's own records. Attach a bounded body (2,000 characters in the proven case) to the error type so every journal that records the error gains the evidence, and journal the exact submitted payload beside the failure. Swallowing an exception without its type and status makes the failure class unrecoverable from the record; the next occurrence starts from zero.
*Episode:* rejections that had required live replay probes became readable directly from the journal once the error carried its body (2026-10-27).

**27. One failure classifier, shared by every path that judges failure.** Retry, drain, and gate paths that classify failures independently will drift apart, and the drift discards work silently at the seam: a transport or account-state 403 treated as terminal by one path and transient by another is lost work. Use a single classifier everywhere (network errors, 429, and 5xx are unavailable and stay queued as deferred; genuine validation rejections are terminal), and split terminal subclasses only on evidence, refining the shared classifier rather than forking it.
*Episode:* two independent classifiers let a 403 be discarded as terminal at drain time; 40 queued items per incident class were silently lost before the paths shared one classifier (2026-10-26).

**28. Latch terminal decisions so futile work is not re-emitted.** Every terminal outcome (a fill, a rejection, and equally a local skip) writes a latch keyed on the full decision tuple, with breaker semantics: open after a threshold, half-open probes that cheaply re-check the gating condition first. Latches invalidate on any relevant state change, only stable reasons are ever cached (never timeouts or rate limits), a per-key token bucket bounds the worst case, and exit or reduction decisions bypass entry latches entirely.
*Episode:* 182 identical re-emissions in one session came from terminal decisions the existing latch never saw because it was keyed on only one side's outcomes; latching all of them collapsed the burst to one evaluation plus a counter (2026-10-19).

## Part VII: The machinery around the machinery

**29. The gate keeps its own receipts.** Never let a display pipe mask a gate's exit code: in POSIX sh a pipeline's status is its last command's, so a runner piped to a tail printer makes the gate incapable of failing. Redirect the runner to a log, capture its code, print the tail for humans, and re-raise the captured code. Recompute gate coverage mechanically on every run (production modules against the tests the gate actually discovers) and fail on a new uncovered module, an undiscovered test file, or a stale exemption; keep exemptions in a dated ledger that can only shrink and whose entries carry an expiry. Persist one proof row per gate run (run ID, tree hash, wall time, per-test phase timings, outcomes, ledger hash) and budget from durations: a budget test fails when a phase, the gate's wall time against its rolling median, or the setup share spikes. Quarantine is a ledger, not a skip: a flaky verdict requires evidence (same tree, differing reruns), the row carries owner, issue, and an expiry, and the test still runs every gate in a loud non-blocking segment.
*Episodes:* a piped tail made a regression gate report green unconditionally until the code was captured before printing (2026-10-26). A hand-listed blocker ledger named 72 files while the tree held 246 test files, 174 of them unclassified (2026-10-19). A 117-second test against a 120-second watchdog, and an 87-second step that became 0.5 seconds with no record to explain it, are why per-run proof rows exist (2026-10-19).

**30. Registries generate their own documents.** One machine-readable registry is the only source for what jobs, products, and checks exist; operational charters and runbooks are generated from it, and a diff test fails on drift. State the invariants as tests over the registry: every entry has an owner, an interval, a deadline strictly less than its timeout, and exactly one dead-man check, never shared between entries. A hand-maintained list drifts silently and then misleads an incident at the worst moment.
*Episode:* a hand-listed charter named 15 jobs including one that did not exist, omitted 2 watchdogs and 14 in-process jobs, and stated a deadline longer than its own timeout (2026-10-19).

**31. Retention: classify at write time, prune by reader census, manifest before delete.** Assign every artifact a retention class at creation (evidence and manifests indefinite; per-run metadata about a year; intermediate state copies days, keeping the last few; scratch hours). Partition facts by time, seal closed partitions into one file each, and expire by dropping whole partitions past a declared horizon. Before pruning any growing store, census its readers and prove nothing reads artifacts past their own cycle; then prune on every save, fail-soft. Before any bulk delete, write a manifest (path, size, hash, run ID, class) that outlives the payload. The pruner is itself a registered job with a dead-man check, runs dry first, and keeps on any ambiguity.
*Episodes:* one per-cycle store grew 197 files and 1.3 GB in a day until a reader census proved pruning to 3 was safe (2026-10-24). A state-copy store reached 23 GB at roughly 640 MB per iteration before tiered retention and content-addressed snapshots collapsed most of the growth (2026-10-19).

**32. Design for the real memory ceiling, and serve big data by reference.** Measure the effective ceiling, not the brochure number: on one proven host a nominal 8 GB yielded about 2.8 GB usable, the remainder held by the host, with swap impossible from inside. Schedule one heavy job at a time on such a host, make migrations stream (iterators, incremental writers, persisted progress, a memory floor guard) instead of loading, and never inline a large dataset into a per-cycle snapshot every worker loads whole. Serve oversized data by reference: pass a small manifest reference (path, manifest hash, build ID, as-of), verify the manifest hash is unchanged at evaluation time, prefilter by manifest metadata so only items that can reach scoring are ever read, stream one item at a time, and give heavy consumers their own timeout class in a separate pool.
*Episodes:* inlining a roughly 4.5 GB rows map would have exhausted the box; a 408-byte reference plus prefiltering read only about 85 of 1,809 items, with byte-identical results (2026-10-31). A multi-GB ledger migration timed out three times on memory until it streamed (2026-10-23).

**33. Price metered data before pulling it.** On usage-billed sources, call the vendor's cost and record-count metadata before every pull, set a budget cap, and prefer batch download (billed once, re-downloadable for a window) over repeated streaming pulls. Buy the pre-joined schema that answers the actual question instead of downloading the full underlying tape and joining it yourself. When a vendor has no historical endpoint for a series you will need, start recording it yourself today; every missed day is unrecoverable history.
*Episode:* one symbol-year of a trades tape priced at tens of gigabytes and hundreds of dollars against about one to two dollars for the pre-joined bar schema actually needed (2026-10-21).

**34. No counted figure before its run returns; report the level achieved.** Never write a test count, census count, or any counted figure into a report or record before the counted run that produces it has returned; a figure written ahead of its run is a fabrication risk, not an estimate, and the correction afterward costs more than the wait. If a draft must exist first, the slot reads "not yet counted". Record the verification level asked and the level achieved as separate fields for backups, reconciliations, and drills, so a degraded check never reports the same green as a full one.
*Episode:* a gate figure of 1,408 was written into three records ahead of its run; the counted run returned 1,346, and all three records had to be corrected (2026-10-29).
