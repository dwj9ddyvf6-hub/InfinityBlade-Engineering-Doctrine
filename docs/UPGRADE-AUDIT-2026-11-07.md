This release strengthens execution, discovery and verification while preserving the doctrine's substantive depth: all eighteen enhancement disciplines, thirty-three incident patterns, specialist methods, complete research fragments and historical decision registers remain available.

The audit began at revision `7ac8d4f4411a08beebe9d20138d5960a0c1b36ba`, containing 88 tracked files. These are baseline coverage figures, not the size of the expanded release.

## Concrete discrepancies corrected

| Finding | Resulting behavior |
|---|---|
| Copying only the core folder omitted the mandatory primer and sibling references. | Installation preserves the source layout; bundles carry a hashed manifest and explicit runtime prerequisites. |
| Source inventories described runnable modules as specification-only and procedure folders as automatic mechanisms. | Every enhancement discipline now separates written procedure, shipped implementation, tested contract and host proof. |
| The verdict skill rejected unit-test evidence even for a function-level claim. | Evidence must match the requested boundary: discriminating unit proof can close a unit contract, while deployment and external effects need their own observations. |
| A chart protocol section marker became an incorrect 2.5 ATR coefficient. | The method names the implemented `tol_atr=0.25` default and preserves its original analytical protocol. |
| Completed bars were treated as permanently unrevisable, file timestamps as byte identity, and rounded differences as safe tolerance checks. | Observed versions remain immutable; correction policies, appropriate content identity and exact decimal boundaries are explicit. |
| Host-specific tool names and absolute paths appeared portable. | Historical recipes remain available with capability mapping and declared external dependencies. |
| Memory's “never delete” rule conflicted with authorized privacy erasure. | Ordinary supersession preserves history; erasure removes sensitive content across controlled derived copies and retains a non-sensitive receipt. |
| Preparation, queue state and imported claims could be mistaken for completed effects. | Runtime contracts distinguish ready, sent, unknown, pending and failed states; receipts and reconciliation determine the stronger claim. |

## Evidence and limits

The new [research report](research/2026-11-07-agent-repository-design.md) and [source ledger](research/2026-11-07-sources.json) record fifteen source groups and code inspected at exact commits in five external repositories. They support design choices; they do not prove universal improvement from reading this repository. The [behavioral evaluation protocol](BEHAVIOR-EVALUATION.md) supplies the missing experimental bridge through paired trials, independent outcome criteria and untouched final cases.

An independent review also caught incomplete runtime-dependency validation and dependency details missing from router output. The revised validator rejects malformed records, unknown required skills and redirected or non-regular metadata; the router exposes the actual prerequisite declarations. At the documentation checkpoint, the structural validator reported 23 skills, 46 Markdown files, 159 valid local targets and 40 Python files parsed without execution, with no errors. The bounded seven-section prompt contract passed, and all twelve isolated repository-tool regressions passed via `python3 -m unittest discover -s tools/tests -p test_repository_tools.py -v`. These are checkpoint observations, not a substitute for the final release gate.

Local validation checks metadata, local resource targets, syntax and registry freshness. Package regressions exercise temporary-state contracts. Neither proves live delivery, broker execution, chart parity with an unavailable engine, or behavior on every model. Release verification must run on the final source state and retain the command output and revision; this report is not itself a passing gate.

External prerequisites remain explicit: chart analysis needs `core.ta_battery`, its render/data inputs and relevant feed access; backtest cross-checking needs the independent pinned oracle; REA workflows need their external toolchain. No live account, messaging route or installed host skill is changed merely by installing or auditing this source. Older research figures remain dated source claims unless a new receipt independently verifies them.
